# NERV — Архитектура (v0.7)

*Статус: этапы 1 (ядро), 2 (реакции, распознавание, названия) и ускорение ядра реализованы. Обновлено: 2026-11-12.*
*Репозиторий: https://github.com/Kitakaze23/NERV*
*Визуальный концепт: https://claude.ai/artifact/DQ3kfXYNY3ykywu8xLBSeD*

## 1. Продукт

Интерактивная 3D-песочница: пользователь добавляет атомы из таблицы Менделеева, атомы взаимодействуют по законам химии, реакции наглядны и эффектны.

- **Аудитория:** от школьников до студентов; «вау-песочница» и базовые (несложные) исследования.
- **Платформа сейчас:** компьютер (desktop).
- **Платформы в архитектуре:** VR и AR.
- **Мультиплеер:** заложен в архитектуру, не реализуется.
- **Отложено:** уроки, звук и тактильная отдача.

## 2. Принятые решения

| Вопрос | Решение |
|---|---|
| Уровень химии | Правила (валентность, VSEPR, шаблоны реакций) + классическое силовое поле UFF |
| Реакции | Да, наглядные; описываются данными (каталог) |
| Механизмы реакций | Только двухчастичные шаги; сложные реакции — упрощённые многошаговые механизмы |
| Ионная связь | Не «пружина»: ионы держит Кулон; для формулы — запись ионной ассоциации |
| Формат каталога | YAML + reaction SMARTS с картой атомов |
| Растворы | Вода как параметр среды (диэлектрик 80) с правилами диссоциации |
| Формулы | Брутто-формула, название из базы, 2D-структура, журнал уравнений |
| Канонизация | Свой канонизатор, общий для сборки и рантайма; RDKit/InChI — только сверка в тестах |
| База названий | Wikidata (CC0, русские названия) + ручная курация школьного ядра |
| Стереохимия | В MVP не учитывается |
| Названия солей/оснований | Генерируются по правилу из таблицы ионов |
| Визуальный стиль | Гибрид «стекло + неон»: спокойная стеклянная база, яркие эффекты только на событиях |
| Движок | Unity 6 + OpenXR (+ AR Foundation для AR) |
| Ядро симуляции | Отдельный модуль на C# (netstandard2.1, C# 9) без зависимостей от Unity; оформлен как UPM-пакет |
| Тесты ядра | Свой мини-раннер без внешних пакетов (`dotnet run`) |
| Химические данные | Текстовые файлы в `core/data`: `compounds.tsv`, `ions.tsv`, `reactions.yaml` (свой мини-разбор YAML, без библиотек) |
| Горение | Радикальная цепь (H, O, OH), а не один шаг: иначе пламя не распространяется |
| Тепло реакций | Энергетически честно: суммарно выделяется ровно заданная доля −ΔH; остальное «уходит в среду» |
| Границы сцены | Опциональная «коробка» с мягкими стенками (иначе газ разлетается) |
| Производительность | Список соседей через сетку ячеек, Кулон отдельно по заряженным, реакции раз в 4 тика: 200 атомов ≈ 0,15 мс/тик |
| Поток | `SimulationHost`: симуляция в фоновом потоке или ручной режим (WebGL), снимки и события — потокобезопасно |
| Энергии связей | Таблица реальных средних энергий (O–O 35, O–H 111, C=O 178 ккал/моль…) вместо 70 × порядок |
| Искра | Нагрев + расщепление связей на радикалы (как электрический разряд) — надёжно запускает цепь |
| Мультиплеер | Командная модель + детерминизм; сеть — позже |
| Масштаб v1 | Небольшой, с возможностью расширения |

## 3. Слои системы

```
Устройства ввода (мышь/клавиатура · контроллеры · руки · взгляд)
        ▼
Слой намерений (Intents): выбрать, схватить, потянуть, поставить атом, повернуть сцену
        ▼  команды
Ядро симуляции (отдельный поток, фиксированный шаг, детерминизм)
   ├─ Слой топологии (правила): какие связи существуют
   └─ Слой геометрии (силовое поле): как молекула выглядит и движется
        ▼  снимки состояния (snapshot) + события
Представление: рендер · UI · звук · тактильная отдача
```

### Принципы
- **Симуляция ничего не знает о показе и вводе.**
- **Ввод через намерения.** Мышь на десктопе = луч из камеры; в VR — луч/захват контроллером; в AR — щипок рукой. Меняется только адаптер.
- **UI в мировом пространстве.** Таблица Менделеева — 3D-панель: у камеры (desktop), на запястье/рядом (VR), на столе (AR).
- **Симуляция в своём потоке**, рендер интерполирует снимки → стабильные 72–90 FPS в VR.
- **Перетаскивание = сила (пружина), а не телепорт.**
- **Масштаб:** симуляция в ангстремах, сцена в метрах, один коэффициент между ними.
- **Время:** регулируемая скорость времени + температура как ручка интерфейса.

## 4. Ядро симуляции

Единицы: Å, фс, а.е.м., ккал/моль, заряд e, K. Шаг интегрирования 0,5 фс.

### 4.1 Слой топологии (правила)
- Валентность по правилу октета: n = валентные e⁻ − заряд; неметаллы n &lt; 4 → n, иначе 8 − n; водород — дуплет; металлы отдают электроны. Примеры: C 4, N 3, N⁺ 4, O 2, O⁻ 1, Cl⁻ 0, Na 1, Na⁺ 0.
- Тип связи: металл + неметалл с |ΔЭО| &gt; **1,2** → перенос электрона (образуются ионы). Порог снижен с классических 1,7, иначе NaH и Na–C получаются ковалентными.
- Образование и разрыв связей; повышение порядка (O–O → O=O, N–N → N≡N), если у пары осталась свободная валентность и рядом нет других партнёров.
- Тип атома UFF по стерическому числу (соседи + неподелённые пары + неспаренные электроны): C с 4 доменами → `C_3`, O в воде → `O_3`, O в O₂ → `O_2`, N в N₂ → `N_1`.
- Шаблонные реакции — этап 2.

### 4.2 Слой геометрии (UFF)
- **Связи — потенциал Морзе** (глубина — из таблицы энергий связей `BondEnergies`, для пар без данных 70 ккал/моль × порядок; жёсткость из UFF): связь может порваться сама при нагреве, слабые (O–O, N–N) — первыми.
- **Углы** — косинусный ряд UFF; углы VSEPR возникают из типов атомов.
- **Ван-дер-Ваальс** — 12-6 UFF, отсечка 6 Å со сдвигом энергии, «мягкое ядро» ниже 0,5·x_ij (линейное продолжение — консервативно).
- **Кулон** — формальные заряды, диэлектрик среды, shifted-force на отсечке 20 Å, сглаживание √(r² + 0,3²) на малых r.
- **Торсионы пока не учитываются.**
- Интегратор — скоростной Верле; термостат Берендсена (τ = 100 фс).

### 4.3 Справочные данные (неизменяемые)

```
Element
  Z, Symbol, NameRu, NameEn
  Mass
  Electronegativity        (по Полингу)
  ValenceElectrons
  CovalentRadius, VdwRadius
  Color                    (палитра NERV)
  Period, Group, TableRow, TableColumn
  Category
  Availability             Enabled | Optional | ComingSoon
```

- Таблица содержит все 118 элементов с раскладкой и категориями; подробные данные — пока только для элементов MVP (H, C, N, O, Na, Cl + опционально S, F). Остальное будет вынесено в файл данных.
- **Типы атомов UFF:** `H_`, `C_3`, `C_2`, `C_R`, `C_1`, `N_3`, `N_2`, `N_R`, `N_1`, `O_3`, `O_2`, `O_1`, `F_`, `Na`, `S_3+2`, `S_2`, `Cl`.

### 4.4 Состояние мира

**Атомы — хранение по столбцам (SoA):** `Positions`, `Velocities`, `Forces`, `Elements`, `Charges`, `Masses` + кэш топологии (`Types`, `BondOrderSums`, `FreeValences`, `LonePairCounts`, соседние связи).

**Стабильные идентификаторы:** `AtomId` = слот + поколение. Индексы меняются при удалении (swap-remove), id — нет; удалённый id никогда не переходит к новому атому.

**Связь:** `Id`, `A`, `B`, `Order` (1–3), `Progress` (0..1), `IsPolar`, `RestLength`.

**Электронный баланс — вычисляемый** из элемента, заряда и суммы порядков связей, отдельно не хранится.

**Ионы:** ионная связь не является пружиной; ионы удерживает Кулон. **Ионные ассоциации** (`IonicGroup`) строятся по близости противоположно заряженных частиц (&lt; 3,6 Å), формула сокращается до формульной единицы (Na₄Cl₄ → NaCl). В среде «вода» ассоциаций нет — ионы показываются по отдельности.

**Молекула — производная сущность**, пересчитывается при изменении топологии (union-find): атомы, формула Хилла, заряд, число связей.

**Кэш топологии** (соседи, типы UFF, параметры связей, углы, исключения 1-2/1-3, молекулы) пересчитывается лениво при изменении связей или зарядов.

### 4.5 Команды и события

**Команды** (через очередь `Enqueue` или немедленно `Apply`; все пишутся в журнал с номером тика):
`AddAtom` · `RemoveAtom` · `AddBond` (заготовки) · `Grab(hand)` · `MoveGrab(hand)` · `Release(hand)` · `SetTemperature` · `SetMedium` · `SetTimeScale` · `Spark`

`HandId` в командах захвата — задел на несколько рук и игроков.

**События** (ядро → представление):
`AtomAdded` · `AtomRemoved` · `BondForming` · `BondFormed` · `BondBroken` · `BondOrderChanged` · `ElectronTransferred` · `TopologyChanged` · `MoleculeIdentified` (название в `Text`) · `ReactionFired` (id реакции в `Text`, индекс записи журнала в `Value`) · `HeatReleased` (кДж/моль в `Value`, пресет эффекта в `Text`).

Журнал реакций `Simulation.ReactionLog` хранит для каждого срабатывания **карту атомов** (номер в шаблоне → атом сцены) — по ней клиент рисует следы и номера атомов.

Эффекты, журнал реакций и прогресс уроков **подписываются на события**, а не опрашивают мир.

**Снимок** (`WorldSnapshot`) заполняется в переиспользуемые массивы — без аллокаций в кадре.

### 4.6 Шаг симуляции
1. Выполнить команды из очереди.
2. Полушаг скорости, шаг координат (Верле).
3. Правила топологии: свободная сборка и перенос электрона → разрыв → повышение порядка. Не больше одной новой связи на атом за тик.
4. Пересчёт сил, второй полушаг скорости.
5. Гашение скорости схваченных атомов, термостат.
6. Рост `Progress` образующихся связей + гашение их относительной скорости.

### 4.7 Решения, найденные при реализации
- **Захват.** Атомы со свободной валентностью в радиусе 3,5 Å притягиваются (потенциал −S(rc − r)²/2rc), а Ван-дер-Ваальс между ними выключен: рекомбинация радикалов идёт без барьера.
- **«Третье тело».** Пока связь образуется, относительная скорость пары гасится (3 % за тик) с сохранением импульса. Иначе энергия ямы Морзе остаётся в двух атомах и они сразу разлетаются. Это и есть выделение тепла при образовании связи — позже его покажет событие `HeatReleased`.
- **Старт связи.** Сила связи сразу 30 %, дальше плавно до 100 % — иначе быстрые лёгкие атомы (H) пролетают друг сквозь друга.
- **Непрерывные потенциалы.** Скачки энергии на отсечках и выключение Кулона для заряженных пар «накачивали» энергию; исправлено (shifted-force, сдвиги, мягкое ядро).
- **Производительность (до оптимизации):** 200 атомов ≈ 1,1–1,6 мс на тик (O(N²)). См. 4.9.

### 4.8 Решения этапа 2
- **Мгновенная смена связей по шаблону** оставляет фрагменты «внутри» друг друга (например, O…O на 1,2 Å → ~900 ккал/моль от отталкивания). Поэтому после срабатывания фрагменты раздвигаются как твёрдые тела (без изменения скоростей), а затем потенциальная энергия до/после сравнивается и кинетическая энергия корректируется так, чтобы суммарно выделилось ровно `ReactionHeatFraction · (−ΔH)`.
- **`ReactionHeatFraction` = 0,3:** в сцене из десятков атомов полный ΔH разогревал бы всё до 20 000 K и сразу разрушал продукты. Событие `HeatReleased` сообщает полный ΔH — для визуализации.
- **Термостат τ = 100 фс.** Пробовали 400 фс (тепло дольше поджигает соседей), но свежесобранные молекулы (O=C=O) разваливались от собственного тепла образования.
- **Контакт молекул — 3,5 Å** (≈ равновесное расстояние Ван-дер-Ваальса H…O). При 3,0 Å столкновения почти не регистрировались.
- **Коробка с мягкими стенками** (`BoxCenter`, `BoxHalfSize`): без неё газ после искры разлетается и реакции затухают. Клиенту она нужна в любом случае как границы сцены.
- **Компенсируется только рост потенциальной энергии.** Если после реакции энергия падает (новая ионная пара притягивается), в тепло это не превращается — иначе продукты получают энергию больше энергии связи и разлетаются.

### 4.9 Производительность и поток
Профиль до оптимизации (200 атомов, с химией): 0,76 мс/тик, из них 0,51 — проверка реакций (O(N²) поиск контактов, аллокации), 0,22 — силы.

Что сделано:
- **Список соседей через сетку ячеек** (`NeighborList`): пространство делится на кубики со стороной = отсечке 6 Å, пары ищутся только в соседних кубиках. Один список на тик используется силами, правилами топологии и поиском контактов реакций; перестраивается только при изменении координат.
- **Исключения 1-2/1-3** — компактные массивы (CSR) вместо хеш-таблицы.
- **Кулон** — отдельный цикл только по заряженным атомам (их мало, а отсечка 20 Å).
- **Реакции** проверяются раз в 4 тика (`ReactionCheckInterval`) с пересчётом вероятности `1 − (1 − p)⁴`; шаблоны отсеиваются по составу молекулы до сопоставления; разбиение на молекулы кэшируется до смены топологии.

| Атомов | До | После |
|---|---|---|
| 100 | 0,28 мс/тик | 0,05 мс/тик |
| 200 | 0,76 мс/тик | 0,15 мс/тик |
| 500 | 2,70 мс/тик | 0,46 мс/тик |

При 3000 тиков в секунду (≈ 1,5 пс симуляции за секунду, `BaseTicksPerSecond`) 200 атомов занимают ~0,45 с процессорного времени в секунду — в отдельном потоке это не мешает рендеру. Бенчмарк: `core/bench/Nerv.Core.Bench` (`SimulationProfile` даёт время по фазам и для отладочного оверлея клиента).

**`SimulationHost`** — точка входа для клиента:
- `Start()` — симуляция в фоновом потоке; `Advance(dt)` — ручной режим из кадра (платформы без потоков, например WebGL);
- `Submit(command)` — команды из ввода (потокобезопасно); выполняются в начале ближайшего шага и пишутся в журнал с номером тика — повтор журнала детерминирован;
- `CopySnapshot(dst)` — последний опубликованный снимок (двойная буферизация, массивы переиспользуются);
- `DrainEvents`, `DrainReactions` — события и записи журнала реакций для эффектов;
- `Paused`, `Settings.TimeScale`, `MaxTicksPerAdvance` (защита от «спирали» после подвисания).

### 4.10 Химические уточнения при оптимизации
- **Таблица энергий связей.** С единой глубиной 70 ккал/моль в пламени копились цепочки HO₆, H₂O₄. Теперь слабые O–O (35) рвутся первыми.
- **Запрет цепочек O–O–O** при свободной сборке (`BondRules`): неустойчивы, а озон без формальных зарядов модель не описывает. Пероксиды (H₂O₂, HO₂) разрешены. Запрет действует и на силу «захвата».
- **Искра = нагрев + радикалы.** Только нагрев поджигал смесь в 30–60 % случаев (тепло рассеивается за доли пикосекунды). Теперь `Spark` расщепляет 2 связи в радиусе (осколки разлетаются, 200 тиков им нельзя соединиться друг с другом) — поджиг в 29 из 30 случаев.
- **Радикальные шаги для метана** (OH + CH₄, O + CH₄, CH₃ + O₂) и для промежуточных продуктов водорода (H + HO₂, H + H₂O₂). Каталог — 15 шагов.

## 5. Реакции (реализовано)

### 5.1 Двухчастичные шаги
Каждая запись каталога — столкновение не более двух частиц. Суммарные реакции раскладываются на упрощённые шаги:
```
H₂ + O₂ → H₂O + O      (шаг 1, нужна искра)
O  + H₂ → H₂O          (шаг 2, быстрый)
```
В UI механизм помечен как «упрощённый», в журнал пишется суммарное уравнение.

**Горение водорода реализовано как радикальная цепь** (первая версия «H₂ + O₂ → H₂O + O, O + H₂ → H₂O» обрывала цепь — пламя не шло):
```
H₂ + O₂ → H₂O + O      инициирование, нужна искра (Ea 95)
O  + H₂ → OH + H       разветвление (Ea 15)
OH + H₂ → H₂O + H      продолжение, −62 кДж/моль (Ea 10)
H  + O₂ → OH + O       разветвление (Ea 30)
H + OH → H₂O, OH + O → HO₂ …   обрыв — делает свободная сборка
```
Для групп с `mechanism: chain` валидатор не сравнивает сумму шагов с итогом (шаги повторяются разное число раз).

**Каталог MVP** (`core/data/reactions.yaml`, 15 шагов): горение H₂ (6: инициирование + радикальная цепь), горение CH₄ (5: через CH₃ и формальдегид), Na + Cl₂ (2), диссоциация HCl в воде, нейтрализация H⁺ + OH⁻ в воде.

### 5.2 Формат каталога (YAML + reaction SMARTS)
```yaml
id: h2_combustion_1
name: Горение водорода — шаг 1
smarts: "[H:1][H:2].[O:3]=[O:4]>>[H:1][O:3][H:2].[O:4]"
activationEnergy: 180      # кДж/моль (игровая шкала)
deltaH: -70
conditions:
  medium: [vacuum, water]
  minTemperature: null
effects: combustion_flash
education:
  summary: "2H₂ + O₂ → 2H₂O"
  textRu: "Водород горит с выделением большого количества тепла…"
  level: school
  mechanism: simplified
tags: [горение, экзотермическая]
```
- Движок поддерживает подмножество SMARTS. **Диалект NERV:** заряд, не указанный в реагентах, означает «заряд 0»; примитивы `Dn` (число связей) и `Hn` (число соседей-водородов); водороды в шаблонах пишутся явно (`[H:2]`).
- **Карта атомов** (`:1`, `:2`…) задаёт, какой конкретный атом куда переходит → анимация реального перехода атомов.

### 5.3 Срабатывание
1. Пространственная сетка находит пары сблизившихся молекул.
2. Индекс каталога отдаёт шаблоны с обоими реагентами.
3. Перебираются все вложения шаблона; первое, где новые связи образуются между атомами ближе 3,5 Å и не нарушаются валентности, получает один бросок «кубика»: `p = rate · exp(−Ea / R·T_эфф)`, T_эфф — кинетическая температура атомов обеих молекул.
4. Изменение топологии по карте атомов → раздвигание фрагментов → баланс энергии и тепло вокруг центра (4,5 Å) → события и запись в журнал.

Не больше одной реакции на молекулу за тик; порядок обхода детерминирован.

`Spark` — сильный локальный нагрев (уже реализован в ядре).

### 5.4 Вода как среда
При `medium: water` работают правила диссоциации:
```
HCl    → H⁺ + Cl⁻
NaOH   → Na⁺ + OH⁻
H⁺ + OH⁻ → H₂O
Na⁺, Cl⁻ остаются в растворе (при выпаривании — кристалл NaCl)
```
Молекулы растворителя не моделируются. Диэлектрик 80 уже ослабляет притяжение ионов в ядре.

### 5.5 Валидация каталога (при сборке)
- Сохранение атомов и заряда.
- Валентности продуктов.
- Сумма шагов совпадает с `education.summary`.
- Автотест на каждую реакцию: реагенты + энергия → ожидаемые продукты.

## 6. Формулы и названия (реализовано)

### 6.1 Что видит пользователь
- **Брутто-формула** (нотация Хилла) — реализована.
- **Название** из базы (основное + тривиальные).
- **2D-структурная формула.**
- **Журнал реакций:** реальные сбалансированные уравнения (`2H₂ + O₂ → 2H₂O`).

### 6.2 Один код канонизации для сборки и рантайма
```
Источник (SMILES из Wikidata)
        ▼
Инструмент сборки ── использует ЯДРО NERV ──┐
   парсер SMILES → наш граф (явные H)         │  один и тот же
   нормализация → канонический ключ           │  код канонизации
        ▼                                     │
   база названий (бинарный файл)              │
                                              │
Рантайм: граф из сцены → нормализация → ключ ─┘ → поиск
```
Расхождение ключей невозможно по построению. Ключ — канонический SMILES в диалекте NERV: все атомы в скобках (`[CH3][CH2][OH]`), явные символы кратных и ароматических связей, несвязанные части отсортированы. Тесты проверяют независимость от записи SMILES и от порядка атомов (240 случайных перестановок, включая симметричные молекулы).

### 6.3 Алгоритм канонизации
1. **Нормализация:** водород с единственной одинарной связью к не-водороду сворачивается в счётчик H (H₂, H⁺, H⁻ остаются атомами); ароматичность — **пока только 6-кольца из C/N** с чередованием связей (пиррол, фуран — позже); резонансные правила — позже.
2. **Инварианты атомов** (Морган / Вейсфейлер–Леман).
3. **Разрыв симметрии:** перебор вариантов, лексикографически минимальный.
4. **Канонический SMILES** — ключ поиска; 64-бит хеш для индекса; полная строка для проверки коллизий.

Стереохимия в MVP не учитывается; позже — стереослой из 3D-координат.

### 6.4 Соли и основания
- Ключ ионной ассоциации: ключи ионов + количества, сокращённые до формульной единицы (Na₄Cl₄ → NaCl).
- **Название по правилу:** анион + катион в родительном падеже («хлорид натрия», «гидроксид калия»).
- Таблица ионов (~30 записей): `ion`, `anionNameRu`, `cationGenitiveRu`.

### 6.5 База названий
Источник — **Wikidata** + **ручная курация** школьного ядра.
```
Compound
  key               канонический SMILES (наш)
  formula
  nameRu            «этанол»
  trivialRu[]       [«этиловый спирт», «винный спирт»]
  nameEn, iupac
  category          кислота | основание | соль | оксид | углеводород | спирт …
  factsRu[]         2–3 факта для школьника   (только в курируемых)
  hazard            «ядовит», «горюч»           (только в курируемых)
  wikidataId
  curated           true | false
```
- **Сейчас:** 84 курируемые записи (простые вещества, радикалы, оксиды, кислоты, соли натрия, углеводороды, спирты, альдегиды, кислоты, эфиры, галогенпроизводные, ароматика). **Цель MVP:** ~300. **Потом:** десятки тысяч автоматических из Wikidata.
- **Таблица ионов:** 33 иона (`core/data/ions.tsv`); соли без записи в базе называются по правилу («Гидросульфид натрия»).

### 6.6 Неизвестное соединение
- Брутто-формула + «неизвестное соединение».
- **Известные изомеры той же формулы** (обучающая механика).
- Статус стабильности.

## 7. Визуализация

Концепт (5 экранов): https://claude.ai/artifact/DQ3kfXYNY3ykywu8xLBSeD

### 7.1 Направление
- **Гибрид «стекло + неон»:** атомы — полупрозрачные стеклянные сферы со светящимся ядром; неоновое свечение, вспышки и частицы — **только на событиях**.
- **Цвета CPK неприкосновенны.** Стиль меняет материал, не цвет.
- Базовый вид дружелюбный и читаемый; глубина — через «Лабораторию».

### 7.2 Визуальный язык
| Элемент | Изображение |
|---|---|
| Атом | ядро цвета CPK + стеклянная оболочка с краевым свечением (fresnel) |
| Свободная валентность | яркие точки на оболочке, направлены по VSEPR (данные: `FreeValences` в снимке) |
| Неподелённые пары | бледные парные точки (данные: `LonePairs` в снимке) |
| Связь | энергетический мостик; число нитей = порядок связи |
| Полярность | градиент мостика к более электроотрицательному атому + δ+/δ− (`IsPolar`) |
| Ион | без мостика; пунктирный ореол + знак заряда |
| Образование связи | неспаренные точки летят навстречу и сливаются в мостик (`Progress`) |
| Опознанная молекула | кольцо-пульс + плавающая карточка с названием |
| Схвачен | сплошное голубое кольцо + пунктирная «пружина» |
| Нестабилен | янтарный пунктирный контур, мерцание |
| Температура | холод — голубой иней; жар — янтарное свечение + сильные колебания |

### 7.3 Режиссура реакции
1. Замедление времени (×0,1) в момент реакции.
2. Следы траекторий атомов по карте атомов + номера атомов.
3. Разрядка по знаку ΔH: вспышка и тепловые волны / иней.
4. Карточка шага реакции.
5. Панель повтора реакции.
6. **VR:** никакой тряски камеры.

### 7.4 Окружение
- **Desktop:** тёмная «пустота лаборатории», еле заметная сетка пола.
- **VR:** то же + горизонт и опора под ногами.
- **AR:** реальная комната; обязательны контактные тени.

### 7.5 Палитра и шрифты

- **Unbounded** — заголовки; **Inter** — интерфейс; **JetBrains Mono** — формулы и числа.

## 12. Риски

- **Растворы:** вода — параметр среды, а не молекулы.
- **Упрощённые механизмы** — явно маркировать в UI.
- **Нестабильная экзотика** при свободной сборке (H₂O₂, радикалы) — флаг «нестабильно», возможен распад.
- **Ошибки канонизатора** — ловить сверкой с InChI/RDKit в тестах.
- **Честность для школьников:** эффекты помогают понять процесс, а не искажают его.
- **Перегруз эффектами:** свечение только на событиях.
- **Производительность на Quest:** на ПК 200 атомов — 0,15 мс/тик; мобильный процессор в 3–5 раз медленнее — для VR может понадобиться меньше тиков в секунду или Burst/Jobs.
- **Детерминизм между платформами** не гарантирован (double) — для сети нужен авторитетный сервер.
- **Распространение пламени:** искра поджигает смесь H₂/O₂ в 29 случаях из 30, но пламя гаснет раньше, чем сгорит вся смесь: остывание (термостат + доля тепла 0,3) обгоняет цепь, остаются HO₂ и H₂O₂. Метан сгорает до CO₂/CH₂O в 4–5 случаях из 6. Баланс тепла — на этапе 4, когда его будет видно глазами.
- **Экзотика свободной сборки** при высокой температуре (H₂O₃, O-цепочки): нужен флаг «нестабильно» и распад.
